id: client-file-organisation
title: Organise a New Client's Shared Drive
summary: >-
  Take a messy shared drive from a new client and turn it into a structure they
  can find things in, then hand it back with a short note explaining what you did.
purpose: >-
  Proves you can impose a structure on someone else's chaos without losing
  anything, which is the most common first task a new virtual assistant is given.
difficulty: beginner
estimatedMinutes: 45
skills:
  - administration-organisation
  - administration-documentation
prerequisites:
  - id: files-and-folders
    reason: The naming and folder conventions this task is assessed against are set out there.
  - id: what-is-a-virtual-assistant
    reason: The task assumes you know what a client means when they ask you to tidy something up.
scenario: >-
  A client runs a small design studio. Their shared drive has been in use for four
  years and has never been tidied. It holds client folders named after people,
  after projects and after dates; three folders called "New folder"; invoices
  mixed in with design files; and a folder of scanned contracts that someone
  started and abandoned half way through. The client has asked you to make it so
  they can find things, and has given you two hours.
requirements:
  - Every client has exactly one folder, named consistently.
  - Every file is findable by someone who did not create it.
  - Nothing is deleted. Anything you are unsure about goes into an archive, not the bin.
  - The structure can be explained in under a minute.
instructions:
  - List every top-level folder and write down what it appears to contain.
  - Decide on one naming pattern for client folders, and write it down before you move anything.
  - Create a structure with no more than three levels below the root.
  - Move files in batches, one client at a time, counting the files before and after each batch.
  - Put anything you cannot place into an archive folder, and note why in the handover.
  - Write a short handover note describing the structure and the naming rule.
deliverable: >-
  An organised folder structure, plus a handover note of no more than 300 words
  stating the naming rule, the folder layout, and anything you archived and why.
evaluationCriteria:
  - id: one-folder-per-client
    description: Each client has exactly one folder, and no client appears twice under different names.
  - id: consistent-naming
    description: A single naming rule is used for every client folder, and it is written down.
  - id: nothing-lost
    description: No file was deleted, and anything uncertain sits in an archive with a stated reason.
  - id: findable-without-help
    description: Someone who did not create the files could locate a specific document from the structure alone.
  - id: handover-note
    description: The handover note states the naming rule, the layout and the archived items, in under 300 words.
hints:
  - Decide the naming rule first. Moving files before you have a rule is how a tidy-up creates a second mess.
  - Count files before and after each batch. A file that was moved is recoverable; a file that was lost is not.
  - If two client folders turn out to be the same company under different names, ask before merging them.
commonMistakes:
  - Naming folders after the work rather than the client, which breaks as soon as a client has two projects.
  - Tidying the folders but never writing the rule down, so the next person invents a different one.
  - Deleting apparently empty folders that turn out to be where a shared link points.
referenceGuidance: >-
  A good answer usually has one folder per client, a date-prefixed subfolder for
  each piece of work, and an archive that is boring and clearly labelled. If the
  handover note needs a diagram to explain the structure, the structure is too
  complicated.
