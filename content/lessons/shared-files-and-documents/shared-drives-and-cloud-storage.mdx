A client's drive is not your drive. It has a structure somebody chose, links that
somebody else relies on, and shared settings that decide who can see what. The
work is to fit in, not to improve it.

## Follow the structure that is already there

Your first hour in a new client drive should be spent reading, not tidying:

1. **Open every top-level folder** and note what it appears to contain.
2. **Look for a naming pattern** — dates first, client first, project first. Copy
   it exactly, even if you would choose differently.
3. **Look for a README, a "start here" or a conventions file.** If it exists, it
   is the rulebook, and it overrides your instincts.
4. **Ask before restructuring.** "Would it help if I moved X into Y?" is a
   question. Moving it is not.

If there is no convention and you are asked to create one, use the structure from
the files-and-folders lesson and write it down somewhere the client can find it.

## Sharing at the right level

Cloud drives give you several levels of access, and the wrong one is a
confidentiality problem rather than an inconvenience:

- **View** — can open, cannot change. The right default for anything you are
  sending to a client or an outsider.
- **Comment** — can suggest. Useful for a draft you want reviewed.
- **Edit** — can change and delete. Give this only to people who are working on
  the file.
- **Anyone with the link** — no sign-in required. This is the setting that leaks
  documents, and it should be the one you almost never use.

Two habits:

- **Share the folder, not the file, when there are several files.** A new file
  added later inherits the folder's permissions; a file shared individually does
  not, and the client will not have access to it.
- **Check the sharing setting before you send.** Every drive shows it next to the
  file. Read it. "Anyone with the link" is visible to anyone the link is
  forwarded to, forever.

## Moving, renaming and deleting safely

Three operations to be careful with, because they affect other people:

- **Moving** a file can break a link someone else sent, and can change who has
  access to it. Prefer **copying** into the right place and letting the client
  decide about the original.
- **Renaming** a file that is linked from a website, a spreadsheet or an email
  breaks that link. If a file has a "copy link" that anyone is using, ask first.
- **Deleting** is rarely necessary. Move it to an archive folder instead — the
  same habit as the files-and-folders lesson, for the same reason. In a shared
  drive, the bin is shared too, and emptying it affects everyone.

## What not to do

Do not use "make a copy" as a way to edit a file, because the drive will slowly
fill with near-identical documents and nobody will know which is current. Do not
change a folder's sharing to make your own work easier. Do not empty the shared
bin.

## Practice

Open a drive you have access to and, without changing anything, write down: the
top-level folders, the naming pattern you can see, and the sharing level of one
folder. Then write the question you would ask before reorganising it.
