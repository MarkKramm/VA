#### The scenario

You have just started supporting **Acme Co**, a small design studio. Files
arrive by email, in a group chat, and through a shared drive, and right now
everything lands in a single folder called "Stuff". The client has already
asked twice for a file you could not find quickly, and it is starting to look
unprofessional.

#### Your task

Set up a folder structure for Acme Co that you could hand to a colleague and
have them find anything without asking you where it is.

1. Create a top-level folder for the client.
2. Inside it, create four folders: an inbox, an active folder, a reference folder, and an archive.
3. Number the folders so they sort in the order you will actually use them.
4. Create three example files in the active folder, named so they sort by date and describe what they are.

#### The naming rule, with one correct example

The naming convention is the part people get wrong, so here is one filename
that works and one that does not:

```text
2026-03-14_AcmeCo_Invoice_March.docx   <- date first, describes the content
AcmeCo invoice FINAL v2 REAL.docx      <- no date, records your editing anxiety
```

The date goes first so the files sort themselves, and the rest describes what
the file **is** rather than what stage you are at with it.
