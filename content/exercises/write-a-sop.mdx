#### Choose the task

Pick a task you do repeatedly and could explain without looking anything up.
Good candidates:

- Filing incoming client documents into a shared drive.
- Preparing a weekly status update.
- Processing a batch of new contacts into a list.
- Setting up a folder structure for a new client.

If you cannot think of one, use: _"Take the files in a shared inbox folder and file
them into the correct client folder, renamed to the house convention."_

#### What to produce

```text
Task:      Filing incoming client documents
Owner:     whoever does this next
Updated:   <date> by <your name>
Trigger:   a new file appears in Clients / _Inbox

1. Open … You should see …
2. For each file, rename it to …
   If the date is not clear, use …
3. Move it to …
   If you cannot tell which client it belongs to, put it in … and add a line to …
4. When the folder is empty, …
   If any file could not be filed, message … with the file name and why.

Exceptions
- If a file looks like it contains something confidential, …
- If two files have the same name, …
```

#### How it will be judged

- **Single-action steps.** "Open the drive and rename the files" is two steps.
- **Exact locations.** A path someone can paste, not "the client folder".
- **The gaps are named.** Every procedure has places where a real person gets
  stuck. Those are the steps that make it useful, and they are the ones people
  leave out.
- **An exception path exists.** What happens when it goes wrong, and who is told.
- **It is maintainable.** A date and a name, and it lives next to the work rather
  than in a documentation folder nobody opens.
